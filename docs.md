# Project Documentation

## Overview

This repository contains a React + Vite frontend, a Python FastAPI backend, and a scikit-learn traffic-speed model. The browser communicates with the backend over HTTP/JSON; model files are loaded only by Python.

**Data limitation:** the checked-in CSV is synthetic demonstration data with illustrative road IDs. It is not observed Mumbai traffic, its IDs do not correspond to verified Mumbai corridors, and model scores do not demonstrate performance on Mumbai roads. The interface names Mumbai as the intended study region while explicitly showing this limitation.

## Project Layout

- `backend/app/main.py`: FastAPI application, CORS, and API routes.
- `backend/app/schemas.py`: Pydantic request and response validation.
- `backend/app/services/prediction.py`: config/data loading, summary, trends, and model inference.
- `backend/app/services/emissions.py`: API adapter for the emissions calculation.
- `src/traffic_ml/`: reusable data preparation, features, training, evaluation, prediction, and emissions logic.
- `frontend/src/api/trafficApi.js`: browser API client.
- `frontend/src/pages/`: overview, exploration, prediction, and model-performance views.
- `configs/config.yaml`: dataset paths, model paths, training split, and congestion cutoffs.
- `data/sample/sample_traffic.csv`: synthetic demonstration dataset.
- `models/traffic_speed_pipeline.joblib`: saved preprocessing/model artifact.
- `reports/model_metrics.json`: metrics produced by model training.
- `tests/` and `backend/tests/`: Python unit, integration, and API tests.

## Configuration

### `configs/config.yaml`

Paths are resolved relative to the repository root unless an absolute path is supplied.

| Setting | Current value | Purpose |
|---|---|---|
| `data.input_path` | `data/sample/sample_traffic.csv` | Input CSV loaded by the data service and training workflow. |
| `data.processed_path` | `data/processed/traffic_clean.csv` | Destination for cleaned data generated by training. |
| `data.timestamp_column` | `timestamp` | Timestamp column name in the input CSV. |
| `data.road_id_column` | `road_segment_id` | Road/sensor identifier column. |
| `data.target_column` | `traffic_speed_kmh` | Regression target in kilometres per hour. |
| `data.model_path` | `models/traffic_speed_pipeline.joblib` | Saved pipeline plus feature-schema artifact. |
| `data.metrics_path` | `reports/model_metrics.json` | Training/evaluation metrics output. |
| `training.test_fraction` | `0.2` | Fraction of distinct timestamps reserved for the final test period. |
| `training.validation_fraction` | `0.15` | Fraction of distinct timestamps reserved for validation. |
| `training.random_state` | `42` | Random Forest seed for repeatable training. |
| `training.model_type` | `random_forest` | Descriptive setting; the current training implementation uses RandomForestRegressor. |
| `congestion.low_speed_max_kmh` | `30` | Upper cutoff for the project-defined High congestion class. |
| `congestion.moderate_speed_min_kmh` | `15` | Lower cutoff used for Severe congestion; the config key name is retained from the prototype. |

Current class boundaries in the implementation are: speed `<= 15 km/h` is Severe; `> 15` and `<= 30 km/h` is High; `> 30` and `< 45 km/h` is Moderate; `>= 45 km/h` is Low. These are prototype thresholds, not official Mumbai definitions.

If you change the input CSV, keep the configured column names aligned with its schema. The loader currently reads CSV. The prediction feature pipeline expects timestamp, road ID, and target history for the selected segment. Numeric model inputs `traffic_volume`, `temperature_c`, and `rainfall_mm` can be missing and are handled by the fitted model imputer; missing target observations are not invented.

### Root `.env`

Copy `.env.example` to `.env`. This file is read only when Uvicorn is started with `--env-file .env`.

| Variable | Default | Purpose |
|---|---|---|
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Comma-separated browser origins allowed to call FastAPI directly. Keep this list limited to trusted frontend origins. |

The model and dataset paths are configured in `configs/config.yaml`; environment variables named `APP_ENV` or `MODEL_PATH` are not read by this implementation.

### `frontend/.env`

Copy `frontend/.env.example` to `frontend/.env` only when the frontend must call a non-default API URL.

| Variable | Example/default | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | Empty in development, or `http://127.0.0.1:8000` | Base URL used by `trafficApi.js`. With no value, Vite proxies `/api` and `/health` to `http://127.0.0.1:8000`. |

`VITE_` values are compiled into browser code. Never place secrets in this file. The development proxy target is configured in `frontend/vite.config.js`; if the backend uses another host or port, update that proxy or set `VITE_API_BASE_URL` and add the frontend origin to `CORS_ORIGINS`.

### Other package configuration

- `backend/requirements.txt` lists FastAPI, Uvicorn, Pydantic, ML/data libraries, and API-test dependencies.
- Root `requirements.txt` lists the ML and original Streamlit prototype dependencies.
- `pyproject.toml` makes `src/traffic_ml` installable in editable mode.
- `frontend/package.json` contains React, Vite, Recharts, and Lucide dependencies and the `dev`, `build`, and `preview` scripts.
- `frontend/vite.config.js` binds the dev server to `127.0.0.1:5173` and proxies API requests to port `8000`.

## Prerequisites

- Python 3.10 or newer (the current project environment was tested with Python 3.14).
- Node.js LTS and npm (the frontend was built with Node.js 24).
- Windows PowerShell commands below assume the repository root is the current directory.

## Install

Create and activate a virtual environment from the repository root:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use a process-scoped policy for this terminal only or call `.\.venv\Scripts\python.exe` directly. Do not change the machine-wide execution policy just for this project.

Install the ML package, API dependencies, and frontend dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -r backend\requirements.txt
python -m pip install -e .
Set-Location frontend
npm install
Set-Location ..
```

If `node` or `npm` is not recognized after installing Node.js, open a new VS Code terminal so the updated user PATH is loaded.

Optional local environment files:

```powershell
Copy-Item .env.example .env
Copy-Item frontend\.env.example frontend\.env
```

The frontend example sets an explicit API base URL. Delete `frontend/.env` or leave `VITE_API_BASE_URL` unset to use the Vite development proxy instead.

## Run the Project

Run the API and web client in separate terminals. Start both from the repository root except where noted.

### Terminal 1: FastAPI

With `.venv` activated:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

To load the optional root `.env` CORS configuration:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload --env-file .env
```

API URLs:

- Health check: `http://127.0.0.1:8000/health`
- Interactive API docs: `http://127.0.0.1:8000/docs`
- OpenAPI schema: `http://127.0.0.1:8000/openapi.json`

### Terminal 2: React + Vite

```powershell
Set-Location frontend
npm run dev
```

Open `http://127.0.0.1:5173`. Stop either server with `Ctrl+C` in that server's terminal.

### Build/preview the frontend

From the `frontend` directory:

```powershell
npm run build
npm run preview
```

The production build is written to `frontend/dist`. Vite's preview server is for local review, not a production deployment server.

## Train and Evaluate the Model

From the repository root with `.venv` active and the project installed with `pip install -e .`:

```powershell
python -m traffic_ml.train
python -m traffic_ml.evaluate
```

Training reads `data.input_path`, cleans and saves the data to `data.processed_path`, writes the trained artifact to `data.model_path`, and writes metrics to `data.metrics_path`. The evaluation command reports metrics for the chronological test period. Training creates a sample CSV if the configured input file does not exist; that generated data is also synthetic.

The prediction endpoint returns `503` if the model artifact is missing. Train the model before using prediction if no model artifact is present.

## API Routes

| Method | Route | Description |
|---|---|---|
| `GET` | `/health` | API status and whether configured dataset/model files exist. |
| `GET` | `/api/summary` | Dataset name/status, coverage dates, counts, and average speeds. |
| `GET` | `/api/segments` | Available dataset road IDs and per-segment summary. |
| `GET` | `/api/trends` | Mean observed speed by hour and represented weekday. Optional query: `segment_id`. |
| `POST` | `/api/predict` | Model speed and congestion estimate for a segment/time. |
| `POST` | `/api/emissions/estimate` | CO₂ estimate from vehicle count, distance, and factor. |
| `GET` | `/api/model-metrics` | Saved model and baseline metrics, or a message if metrics are absent. |

Example prediction body:

```json
{
  "road_segment_id": "ROAD_01",
  "forecast_timestamp": "2024-01-03T00:00:00",
  "traffic_volume": 500,
  "temperature_c": 20,
  "rainfall_mm": 0
}
```

`traffic_volume`, `temperature_c`, and `rainfall_mm` are optional. Omitted values are reported in `missing_inputs` and passed through the model's fitted imputer. The prediction needs at least one earlier observation for that segment. A one-hour horizon is the only currently validated horizon; longer horizons are not validated.

Example emissions body:

```json
{
  "vehicle_count": 500,
  "segment_length_km": 2,
  "emission_factor_g_per_vehicle_km": 180,
  "observation_period": "per hour",
  "emission_factor_source": "Illustrative prototype factor; not locally sourced"
}
```

The estimator computes vehicle-kilometres as `vehicle_count * segment_length_km`, then CO₂ grams as `vehicle_km * emission_factor_g_per_vehicle_km`. The default factor is illustrative. Replace it with a cited source and document vehicle category, year, and assumptions before reporting the result as a research estimate.

## Troubleshooting

- **Frontend says API unavailable:** confirm FastAPI is running on port `8000`; check `http://127.0.0.1:8000/health`. Check `VITE_API_BASE_URL` and the proxy in `frontend/vite.config.js`.
- **Browser CORS error:** add the exact frontend origin, including scheme and port, to `CORS_ORIGINS`; if using `.env`, start Uvicorn with `--env-file .env`.
- **Prediction returns `503`:** train the model with `python -m traffic_ml.train` and check `data.model_path`.
- **Prediction returns `404`:** select a segment ID returned by `/api/segments`; IDs are dataset identifiers, not named or geocoded corridors.
- **Prediction returns `422`:** check the timestamp, positive/valid numeric constraints, and that the forecast is later than at least one historical reading for the selected segment.
- **`traffic_ml` cannot be imported:** from the repository root activate `.venv`, then run `python -m pip install -e .`.
- **PowerShell cannot activate `.venv`:** run the environment executable directly or use a process-only execution policy; avoid changing machine policy.
- **`npm` is not recognized:** restart the VS Code terminal after installing Node.js, or add the Node.js installation directory to the current terminal's PATH.
- **Port is already in use:** stop the process using it or choose another server port. If changing Vite's port, update the corresponding allowed CORS origin and the backend proxy configuration.

## Data and Responsible Use

- Dataset coverage reported by the API describes the rows present in the configured file only.
- The checked-in sample contains 144 synthetic rows for three illustrative IDs over Jan 1–2, 2024. It has no verified Mumbai geography, source portal, or local traffic measurements.
- Do not identify sample IDs as Western/Eastern Express Highway, LBS Marg, Bandra–Kurla Complex, or any other real corridor.
- Do not describe the dashboard as live traffic or the emissions result as measured emissions.
- Replace the sample only with a documented dataset whose source, license, geography, period, units, and transformations have been verified.
